# TokWatt — an open, boundary-annotated database of AI inference energy

**Version 0.1.0 (2026-10-25) · Data: CC BY 4.0 · Code: MIT**

Published estimates of "how much energy one AI prompt uses" differ by one to three orders of magnitude. Most of that spread does not come from physics. It comes from **what is counted** (GPU only, the whole server, idle capacity, data-centre overhead, hardware manufacturing) and **what is being done** (a short answer, a reasoning chain, an agent that makes dozens of model calls, an image, a video).

TokWatt collects first-hand estimates from company disclosures, measurement studies and models, records each one with its **measurement boundary** and **functional unit**, and derives harmonized per-task reference values with explicit, reproducible rules.

## What is inside

| File | Rows | Content |

| `data/sources.csv` | 22 | Bibliographic record for every source (DOI or URL, date, type, peer review) |
| `data/task_defaults.csv` | 19 | Derived central / low / high Wh per task (generated by `scripts/build.py`) |

| `data/token_factors.csv` | 6 | Energy per million tokens (input, output, cache read) from published estimates |

| `data/grid_carbon.csv` | 220 | Life-cycle carbon intensity of electricity by country (Our World in Data / Ember) |

## Reference values (v0.1.0)

Harmonized to "server + facility overhead". Central = median of the task's reference set; range = widest reported interval.

| Task | Central (Wh) | Range (Wh) | Estimates | Sources |
|---|---:|---:|---:|---:|
| Short chat answer | 0.34 | 0.16 – 0.99 | 7 | 5 |
| Chat over a long document (~10k tokens in) | 2.9 | 2.5 – 6.0 | 3 | 2 |
| Reasoning answer | 4.7 | 1.1 – 34 | 10 | 2 |
| Generate one image | 1.2 | 0.63 – 13 | 3 | 2 |
| Generate one short video (~5 s) | 124 | 4.3 – 944 | 3 | 2 |
| One task delegated to an AI agent | 150 | 60 – 290 | 1 | 1 |
| One coding-agent session | 321 | 41 – 1,200 | 2 | 2 |

Single-source tasks are flagged in `task_defaults.csv` (`n_sources = 1`) and should be read as indicative.

## Boundary harmonization

Each estimate records five boundary components (`incl_accelerator`, `incl_host`, `incl_idle`, `incl_overhead_pue`, `incl_embodied`). `scripts/build.py` scales values to a common "server + facility overhead" boundary:

- accelerator-only values × **1.72** (Google's measured production ratio from accelerator energy to its comprehensive boundary; sensitivity value 2.0)
- server-level values without data-centre overhead × **PUE 1.13** (median of hyperscaler values used in the literature)
- values that already include overhead, that use a GPU-doubling heuristic, or whose boundary is undisclosed are left unchanged (and flagged)

Both parameters live in `data/parameters.csv` and can be overridden: `python scripts/build.py --factor-accel 2.0 --pue-ref 1.2`.

A built-in sanity check: Google's accelerator-only value (0.10 Wh) × 1.72 gives 0.17 Wh against its measured comprehensive 0.24 Wh, because the narrow figure was also sampled from the most efficient data centres. Harmonization reduces boundary differences; it does not remove utilization differences.

## The "1 billion people" rule

If one billion people each used *E* watt-hours of AI per day, the average power draw would be *E* / 24 gigawatts. Every 24 Wh per person per day is roughly one large nuclear reactor running continuously. The TokWatt app uses this rule.

## The TokWatt app

`app/index.html` is a self-contained calculator built on these tables: count a day's AI use, get watt-hours with a plausible range, cost, CO₂e for any country's grid, a shareable receipt image, and the "1 billion people" scale-up. It also holds the energy ladder chart, the evidence explorer and CSV downloads. It runs from any static host (GitHub Pages works from the repository root or `/app`).

`app/tokwatt.html` is the same page without the document wrapper, used for the hosted Claude artifact. Both carry an embedded copy of `data/`, so rebuild them after any data change.

## Quick start

```python
import pandas as pd
est = pd.read_csv("data/estimates.csv")
src = pd.read_csv("data/sources.csv")
df = est.merge(src[["source_id", "short_name", "url"]], on="source_id")
df[df.task == "chat_reasoning"].sort_values("energy_wh_harmonized")[["model", "host", "energy_wh_harmonized", "short_name"]]
```

Rebuild and check after any edit (Python 3 standard library only):

```bash
python scripts/build.py && python scripts/validate.py && python scripts/build_app.py
```

Refresh grid carbon intensity from Our World in Data:

```bash
python scripts/update_grid_carbon.py path/to/owid-energy-data.csv
```

## Known limitations

- No first-hand per-query figures exist for most closed models; many rows are models of production systems, not measurements of them.
- Agentic estimates rest on token logs and per-token factors, with the cache-read energy ratio as the largest unknown.
- Video estimates come from open models at modest resolutions; frontier closed video systems are not covered.

## Paper

The article describing TokWatt is in `paper/` (LaTeX). `python paper/analysis.py` regenerates every database-derived number, table and figure it contains; see `paper/README.md` for the build.

## Contributing

A new row needs: a first-hand source with a stable URL or DOI, the functional unit, the reported value and unit exactly as published, the five boundary flags, and a locator (table, figure or section). Run `scripts/validate.py` before opening a pull request.
